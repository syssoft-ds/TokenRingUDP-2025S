traceroute sendet wiederholt ICMP Echo requests an den Ziel host, hier anu.edu.au
Jedes dieser Pakete hat eine time to live (TTL), die festlegt, wie oft das Paket weitergeleitet wird.
Jeder Router, der das Paket weiterleitet, verringert die TTL um 1 bis diese den Wert 0 erreicht und
nicht mehr weitergeleitet, sondern verworfen wird. 
Sobald ein Router ein Paket verwirft, sendet er eine ICMP-Antwort Typ 11: "Time exceeded" mit Code 0: 
"Time to live exceeded in transit" an den Sender. Durch die ICMP Antwort erhaelt traceroute die IP des 
entsprechenden Routers und gibt diese zusammen mit der Uebertragungsdauer in Millisekunden aus, z.B.

1  _gateway (192.168.1.1)  0.554 ms  0.733 ms  0.896 ms

liefert und erhoeht fuer jeden folgenden host die TTL der Pakete um 1 bis entweder der Zielhost erreicht 
wird oder - falls festgelegt - die maximale Anzahl an hops erreicht ist. Hier wurde der Zielhost nach

Der TCP SYN scan ist schneller, da fuer TCP einen 3Way Handshake verwendet, wobei ein 
SYN/ACK signalisiert, dass ein PORT offen und ein RST signalisiert dass ein Port 
geschlossen ist. Lediglich bei gefilterten Ports kann es vorkommen, dass mehrere Pakete 
gesendet werden, ohne dass eine Antwort zurueckkommt.
UDP verwendet hingegen keinen Handshake. Ports werden als geschlossen markiert, 
falls sie einen "ICMP unreachable error Type 3 Code 3" zurueckliefern, und als 
gefiltert markiert, falls sie "ICMP unreachable errors Type 3 Code 0,1,2,9,10 oder 13" 
zurueckliefern. Schliesslich werden Ports als offen sowie z.T. als  gefiltert markiert, 
wenn sie nach wiederholtem senden von Paketen keine Antwort zurueckliefern. Wiederholtes 
Senden ist notwendig, um einen Verlust von Paketen auszuschliessen.
Langsamer ist der UDP Scan dadurch, dass fuer offene / gefilterte Ports Nachrichten 
wiederholt gesendet und auf (keine) Antwort gewartet werden muss. Problematischer ist 
allerdings, dass viele hosts die Anzahl an "ICMP port unreachable messages" beschraenken, 
die signalisieren, dass ein UDP port geschlossen ist. Zum Beispiel beschraenkt der 
Linux 2.4.20 Kernel "destination unreachable messages" auf 1 pro sekunde 
(Siehe net/ipv4/icmp.c) 
Derartige Beschraenkungen werden von nmap automatisch erfasst und die Frequenz in der 
UDP Anfragen geschickt werden, wird automatisch an die Beschraenkung angepasst, um zu 
verhindern, dass das Netzwerk mit UDP Paketen ueberschwemmt wird, die der Zielrechner 
ohnehin verwirft.
Um  die Geschwindigkeit von UDP scans zu erhoehen, koennen mehrere Zielrechner parallel 
gescannt werden: Mit --min-hostgroup <numhosts> und --max-hostgroup <numhosts> kann die 
Groesse der parallel zu scannenden Gruppen bestimmt werden und mit --min-parallelism <numprobes> 
und --max-parallelism <numprobes> kann die Anzahl der parallelen Tests festgelegt werden.
Weiterhin kann durch --min-rtt-timeout <time>, --max-rtt-timeout <time> und 
--initial-rtt-timeout <time> die Zeit festgelegt werden, die nmap auf Antwort eines Porttests
wartet. Ferner kann die Anzahl der Versuche fuer einen Porttest mit --max-retries <numtries>
festgelegt werden. Ausserdem kann mit --host-timeout <time> festgelegt werden, wann langsame 
Zielrechner uebersprungen werden. Die Zeit die nmap zwischen zwei Porttests wartet, kann mit 
--scan-delay <time> und--max-scan-delay <time> angepasst werden und die Scanrate, d.i. die 
Menge an Paketen, die nmap in einer Sekunde sendet, kann direkt mit --min-rate <number> und 
--max-rate <number> festgelegt werden. Die Anpassungen, die nmap aufgrund von Beschraenkungen
fuer ICMP Fehlermeldungen, vornimmt, koennen mit --defeat-rst-ratelimit und 
--defeat-icmp-ratelimit deaktiviert werden.
Schliesslich kann zunaechst nur eine Auswahl wichtiger Ports  und nicht die gesamte 
port range eines Zielhosts  gescannt werden.
